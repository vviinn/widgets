# Search Page

Using `Vviinn Widgets` as separate components allows for greater control over the layout of the widgets and supports a wider range of use cases. For example, you can combine `Text Search` and `Visual Search` functionality while refining results with filters, and display them on the same page or even on different pages.

## Available Components

- [vviinn-text-search](?path=/story/widgets-search--text-search) - a text search input field that allows users to search by text or upload an image
- [vviinn-filters](?path=/story/elements-filters--main), [vviinn-extended-filters](?path=/story/elements-filters--extended) - a set of filters that allow users to refine their search results
- [vviinn-results](?path=/story/elements-product-listing--static-filters) - a container that displays the search results

## Examples

### Using Results on a Different Page

This is the most common use case where the search component is on one page (e.g., homepage) and results are displayed on a separate search results page.

#### Automatic Redirect (Recommended)

Set the `results-page-url` prop on the search component. The widget handles redirection and URL parameter passing automatically.

<div id="automatic">
  <div className="tab tab-reverse">
      <div className="tablink-group">
        <button className="tablink tablink--sm" onClick={(e)=> {clickHandlers(e, 'Details_auto', 'automatic')}}>Technical Details</button>
        <button className="tablink tablink--sm active" onClick={(e)=> {clickHandlers(e, 'Code_auto', 'automatic')}}>Code</button>
      </div>
  </div>

  <div id="Code_auto" className="tabcontent" style={{display:"block"}}>
```html
<!-- Homepage -->
<vviinn-text-search
  token="YOUR_TOKEN"
  mode="extended"
  locale="en-US"
  results-page-url="/search"
></vviinn-text-search>

<!-- Results page (/search) -->
<vviinn-text-search
  token="YOUR_TOKEN"
  mode="extended"
  locale="en-US"
  results-page-url="/search"
></vviinn-text-search>

<vviinn-filters locale="en-US"></vviinn-filters>
<vviinn-extended-filters locale="en-US"></vviinn-extended-filters>

<vviinn-results
  token="YOUR_TOKEN"
  locale="en-US"
  product-details-new-tab="true"
  results-page-url="/search"
></vviinn-results>
```
</div>
<div id="Details_auto" className="tabcontent">
How it works:

1. When the user searches on the homepage, the widget redirects to the results page with URL parameters (e.g., `/search?query=shoes` or `/search?searchId=abc-123`). URL param names can be customized via `results-page-params` (e.g., `results-page-params="query=q&searchId=sid"` → `/search?q=shoes&sid=abc-123`). Set this prop on both the search component and `vviinn-results` so they agree on the param names.
2. On the results page, `vviinn-results` with `results-page-url` set automatically parses URL parameters and triggers the corresponding search.
3. The `vviinn-text-search` input is automatically populated with the query from the URL.
4. On the results page, `results-page-url` ensures that the widget does not redirect again — subsequent searches update results in-place.
5. You can intercept the redirect by listening to the `vviinnRedirect` event and calling `event.preventDefault()` (e.g., for SPA routing).
6. Visual search (`vviinn-vps-button`, `vviinn-vps-widget`) supports the same flow: set `results-page-url` and `show-results-in-modal="false"` to redirect to the results page after image upload instead of rendering results inside the modal.
</div>
</div>

#### Manual Redirect

For full control over the redirect logic, omit `results-page-url` and handle navigation yourself using events.

<div id="manual">
  <div className="tab tab-reverse">
      <div className="tablink-group">
        <button className="tablink tablink--sm" onClick={(e)=> {clickHandlers(e, 'Details_manual', 'manual')}}>Technical Details</button>
        <button className="tablink tablink--sm active" onClick={(e)=> {clickHandlers(e, 'Code_manual', 'manual')}}>Code</button>
      </div>
  </div>

  <div id="Code_manual" className="tabcontent" style={{display:"block"}}>
```html
<!-- Homepage -->
<script>
  document.addEventListener("vviinnTextSearchStarted", ({ detail }) => {
     // Redirect using detail.query (text search)
  });

  document.addEventListener("vviinnImageUploadFinished", ({ detail }) => {
    // Redirect using detail.searchId (image search)
  });
</script>
<vviinn-text-search
  token="YOUR_TOKEN"
  mode="extended"
  locale="en-US"
></vviinn-text-search>

<!-- Results page -->
<script>
  // Get query or searchId from URL
</script>
<vviinn-filters locale="en-US"></vviinn-filters>
<vviinn-extended-filters locale="en-US"></vviinn-extended-filters>

<!-- Text Search example: -->
<vviinn-text-search
  token="YOUR_TOKEN"
  mode="extended"
  locale="en-US"
  search-query="RECEIVED_QUERY"
></vviinn-text-search>

<vviinn-results token="YOUR_TOKEN" locale="en-US" product-details-new-tab="true"></vviinn-results>

<!-- Image Search example: -->
<vviinn-cropper token="YOUR_TOKEN" width="300"></vviinn-cropper>

<vviinn-text-search
  token="YOUR_TOKEN"
  mode="extended"
  locale="en-US"
></vviinn-text-search>

<vviinn-results token="YOUR_TOKEN" search-id="RECEIVED_SEARCH_ID" locale="en-US" product-details-new-tab="true"></vviinn-results>

```
</div>
<div id="Details_manual" className="tabcontent">
In this example, the `vviinn-text-search` component is on the first page, and the rest of the components are on the second page.

1. First, you should add event listeners to capture the `query` for a text search or `searchId` for a Visual Search.
2. Pass this data to the second page via URL and use it to get the results.
    * For Text Search, use the `search-query` attribute to pass the query to the `vviinn-text-search` component.
    * For Visual Search, use the `search-id` attribute to pass the searchId to the `vviinn-results` component. To show an image, use the `vviinn-cropper` component. Default value of the attribute `save-image-mode=once` will allow the Cropper to reuse the uploaded image.
</div>
</div>

    </tr>
    <tr>

## Integration

To integrate the components into your project, install the `vviinn-widgets` package using one of the methods mentioned in the [Installation](?path=/docs/getting-started-installation--docs) section. Ensure you install at least version [2.76.1](https://www.npmjs.com/package/vviinn-widgets/v/2.76.1) of the package to use the components. However, using the latest version is recommended.

You can use the components in a framework-agnostic way or integrate them into your project using a specific framework. The components can be used together or separately, depending on your needs. They are highly customizable and suitable for a wide range of use cases.

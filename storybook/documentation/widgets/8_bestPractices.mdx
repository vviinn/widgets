# Best Practices

### Showing initial Text Search results after redirecting to the Results Page

If you are performing a text search and displaying the results on a different page, prefer passing your **query** from the URL as a **`search-query`** parameter to the `<vviinn-text-search>` component, if it exists on the results page.

### Using Text Search or Visual Search on the Results Page

When you have already **redirected and displayed the initial results** using the `searchId` or `query` parameter from your URL, follow these best practices:

- **For later searches on the same page, you don't need to pass any parameters again;** the components will handle the new query or image upload. Passing parameters again could lead to unexpected behavior.
- **To support page reloads** (or navigating back, e.g., from the Product Details page), you should **update the URL after each new search** without refreshing the page. If you don't use a SPA framework, you can use the [pushState](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState) or [replaceState](https://developer.mozilla.org/en-US/docs/Web/API/History/replaceState) methods from the browser history API.
- **To save the image between page reloads**, use the `save-image-mode="always"` parameter for the `<vviinn-cropper>` component.
